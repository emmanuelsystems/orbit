# ORBIT Concepts

## Product promise

**Every meeting closes the loop.**

ORBIT treats a recurring meeting as a continuing Mission rather than a sequence of isolated transcripts.

## Vocabulary

| ORBIT term | Meaning |
| --- | --- |
| Mission | A recurring meeting series |
| Orbit | One occurrence of the Mission |
| Commander | Human ultimately responsible for the Mission |
| Mission Control | The agent operating layer |
| Mission Charter | Purpose, cadence, participants, authority, boundaries |
| Mission State | Reviewed durable context carried forward |
| Telemetry | Bounded evidence and supporting sources |
| Briefing | Pre-meeting preparation |
| Flight Recorder | Exact primary transcript |
| Recorder Analyst | Extracts evidence, decisions, actions, owners |
| Systems Analyst | Reviews workflow, friction, handoffs, opportunities |
| GO | Explicit authorization from the proper human authority |
| NO-GO | Explicit rejection, pause, or hold |
| PENDING | A decision is required |
| OBSERVED | Evidence/discussion exists but no decision was made |
| Flight Plan | Authorized actions resulting from the Orbit |
| Dispatch | Routing authorized work to a destination |
| Debrief | Review of an Orbit's usefulness and operation |

## Metaphor boundary

The ORBIT vocabulary should make the product memorable without hiding implementation details.

User-facing concepts may be themed, while internal artifact names remain understandable and searchable. For example, the user-facing Flight Plan is recorded in `decision-action-register.md`.
